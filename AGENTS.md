# dsh-artifact-studio

- Read `/home/parth/Documents/deepseek-harness/default-workspace/docs/features/FEAT-002-artifact-studio.md` before changing behavior, contracts, or storage, and update it in the same change.
- TypeScript, ES modules. The host lives in `src/host/` and compiles to `dist/` with `tsc`. The browser client is bundled from `src/client/` by esbuild into `client.js`, plus the lazy `client.doc.js` that carries Tiptap and `client.sheet.js` that carries the grid and the formula engine, and `client.board.js` that carries Excalidraw. `src/contract.ts` and `src/render.ts` are shared by both halves.
- Three host plugins come from one package. `dsh-artifact-studio` registers the `/artifacts-rpc` route. `dsh-artifact-studio/tools` registers the fourteen tools. `dsh-artifact-studio/skill` registers the bundled `artifact-design` skill from `src/host/lib/skill.ts`; it is separate so a composition without `skills` still loads the tools. The route and tools build an `ArtifactService` over the same files, and `store.ts` serialises writes per artifact directory inside the process and takes an exclusive write-lock file beside it.
- Page previews use `sandbox="allow-scripts"` with no other flags, plus the injected CSP in `src/render.ts`. Do not add `allow-same-origin`. The Web shell has no CSP of its own.
- `composePage` emits the policy, charset, title, and token style as a prologue and puts the artifact inside the body. Never go back to injecting into the page's own `<head>`: a comment or a leading script can defeat a pattern match, and the policy must be parsed before any page byte. The print frame is the one place `allow-modals` appears, because `print()` requires it.
- Every write and delete target goes through `assertWithin` before touching disk, and every lock through `withLock`. A link planted at any level of the tree must fail, not be followed.
- Chrome uses `@deepseek-ai/dsh-client-ui-primitives` (Button, Menu, Modal, Toast, SegmentedControl, SegmentedTabs, ZoomControls, Switch, Input, CodeBlock, TextShimmer, icons). The Web shell provides it to plugin bundles at runtime, so `scripts/build.mjs` marks it external. It ships no types: `src/client/primitives.d.ts` declares only what the plugin uses, from the package source in the installed Harness. Tests load `tests/primitives-stub.cjs` in its place. Icons must be exported names; a missing sprite symbol renders nothing.
- Plugin chrome colors come from `--dsw-*` tokens. The Harness marks dark mode with `data-ds-dark-theme` on `<body>`, not `data-theme`; `src/client/theme.ts` watches it.
- A page follows the dark token colors only when it opts in with `<meta name="color-scheme" content="light dark">`; `composePage` then sets `data-artifact-theme`. Pages without the meta keep the light colors, because they may paint literal light backgrounds.
- Token JSON uses `actionText`; CSS uses `--artifact-color-action-text`. Legacy saved palettes gain missing neutral/action roles at read time without rewriting their files. The bundled skill resolves `examples/page-design-system.html` relative to its compiled module; keep that reference in the npm files list. It needs renderer-injected tokens, not bare-file viewing.
- Every visible string goes through `t()` with EN and ZH entries in `src/client/locale.ts`. Test AC-023 enforces this.
- Runtime dependencies are MIT only. A build-time dependency bundled into a client chunk may be MIT, Apache-2.0, or BSD-3-Clause, and each ships in `THIRD_PARTY_NOTICES.md`. `tests/package.test.mjs` checks the runtime ones. fast-formula-parser is MIT; its bundled transitive dependencies chevrotain and bessel are Apache-2.0 and are named in the notices. Excalidraw is MIT; its bundled fonts are SIL OFL 1.1 and are named in the notices.
- `npm test` builds first. A live check needs the bundle reinstalled, through `remove_bundle` then `install_bundle`, and then a window reload.

- A sheet artifact stores one JSON workbook in `content/sheet.json`. The model, formula evaluation, operations, and views live in `src/sheet/` and are imported by both the host and `client.sheet.js`. The canonical JSON shape is documented in `src/sheet/model.ts` and the FEAT-002 sheet section; never store a second shape.
- Sheet content is validated and canonicalised in `service.create` and `service.update`; every sheet write must pass through `parseSheetWorkbook` and `serializeSheetWorkbook`. `artifact_sheet_update` validates an operations array before applying it, and a stale `baseVersion` is refused like any other write. Sheets have no recipes and no pinned generation snapshot; `artifact_rebase` refuses them.
- Board content is validated and canonicalised in the same service path through `src/board.ts`. `artifact_board_update` applies element operations after reading the scene. Sheets and boards skip recipes and pinned generation snapshots, and `artifact_rebase` refuses them. A board exports as a native `.excalidraw` file from the host; PNG and SVG are rendered in the browser by Excalidraw and downloaded by the panel, never by a host renderer.
- Excalidraw 0.18.1 is a build-only devDependency bundled into `client.board.js`: it is MIT, React 18 compatible, and kept out of the main bundle. Its own toolbar, menus, and translations are the approved exception to the Harness-primitives and `t()` chrome rules. Disable AI and embeddable elements, keep file load/save out of its UI, and self-host every font and the font-subset worker under the fixed `/artifacts-whiteboard/` route. A missing font makes Excalidraw fall back to its CDN, so the asset copy and manifest are security-relevant.
- Formula evaluation is `src/sheet/formula.ts` over fast-formula-parser 1.0.19 (MIT), wrapped with circular-reference detection, a bounded evaluation budget, dependency pre-resolution (the parser is not reentrant), and Excel-like error propagation for top-level aggregates. The parser leaves common functions such as MAX, MIN, MATCH, SUMIFS, and TEXTJOIN as stubs; `src/sheet/functions.ts` implements them and overrides INDEX for cross-sheet ranges. The host imports it for CSV, XLSX, print, and warnings, so the panel and exports agree. XLSX packaging is `src/host/lib/xlsx.ts` with fflate (MIT); do not add a second spreadsheet engine or a second formula engine.
- The sheet grid is a virtualized DOM grid in the lazy chunk, not a canvas and not a third-party spreadsheet UI. Its chrome uses the Harness `--dsw-*` tokens; cell fills and text colors are artifact content. A fill with a missing or low-contrast text color gets a readable default in the panel, print, and XLSX without rewriting the stored style, and an explicit pair below 4.5:1 returns a `low-contrast` warning. CSV exports the first sheet; XLSX exports every sheet with styles, formulas, and cached results.
- A board artifact stores a native Excalidraw scene in `content/board.excalidraw`. The host-side shape, validation, element factory, and operations live in `src/board.ts`; the panel imports the same validator for gallery thumbnails. Never import `@excalidraw/excalidraw` in the host or the main client bundle; only the lazy `client.board.js` chunk may mount it.

- The user-visible name for a design artifact is Mockup (原型). The stored type, the tool argument, and code identifiers stay `design`.
- Design artifacts store Design JSX in `content/design.jsx`. The native `.fig` is derived on export and never stored as content. In the host, only `src/host/worker/design-worker.ts` and `src/host/lib/design-render.ts` may import `@open-pencil/*`; in the client, only `src/client/canvas/`. Never call `renderJSX` in the host process or a tool.
- The design worker is a child process run with Node's permission model: it reads only the plugin package and its installed modules, and has no network, no file writes, and no child processes. Icons come from the bundled Material Design Icons set through `src/icon-set.ts`; never fetch Iconify at runtime. The 20 s deadline kills a hung or hostile source.
- `src/icon-set.ts` is the one shared module the worker and the canvas chunk both import. It may import `@open-pencil/core/icons` and must stay free of Node APIs. The icon file and the bundled families live in `assets/`, which the build fills from `@iconify-json/mdi` and `roboto-fontface`.
- Design previews are derived files at `<artifact>/preview/<sha256>.png` plus a `.json` summary. They are never versioned and never hashed as content; delete them freely.
- A design also exports a self-contained view-only HTML page through `artifact_export` format `html`. It carries the precompiled `.fig` scene, the lazily built `assets/canvas.viewer.js`, CanvasKit, and the bundled faces, all gzipped inline and decoded with `DecompressionStream`; the page runs under `connect-src blob:` and makes no request. Never put Design JSX or the icon set in that page, and never add a fetch path to the viewer entry.
- A design also exports a second, smaller page through format `html-svg`: the engine SVG for the shapes, with real HTML text boxes on top and only the families the design uses. Keep every text node as HTML, because the engine SVG cannot wrap text. Take each box's placement and rotation from `getWorldMatrix`, and honour the model's wrap flag, because hug-width text is painted as one line that overflows.

- The in-panel canvas is the lazy `client.canvas.js` chunk built from `src/client/canvas/`. It is the only client code that may import `@open-pencil/*`; the host imports the engine only through `design-worker.ts` and `design-render.ts`. It never writes: it serializes the page with `selectionToJSX` and hands the text to the tab's draft.
- Engine files (CanvasKit, the bundled fonts, and the icon set) are served only from the fixed list in `src/host/lib/assets.ts` at `/artifacts-canvas/`. Never join a request path to a filesystem path, and never serve artifact content from that route. `scripts/build.mjs` copies the files into `assets/`, which is generated and gitignored.
- The design canvas exposes a typed snapshot and mutation handle from `src/client/canvas/entry.ts`. A hidden Vue component (`src/client/canvas/bridge.ts`) reads the SDK's composables and fills the snapshot. The inspector is React (`src/client/design-inspector.tsx`), lives in the tab's right drawer, reads only the snapshot, and writes only through the handle. There is no Vue rail. View is the default mode and must not change the document.
- Ctrl or Cmd wheel zoom is caught on the surface wrapper in `src/client/canvas/surface.ts` in the capture phase, before the engine's canvas listener, because the engine applies 4x per notch. The range and the wheel and pinch steps live in `src/client/canvas/zoom.ts`. Plain wheel panning stays with the engine.

- `src/client/editor-model.ts` owns one shared editor per full artifact address. Draft and in-flight write state are separate. Only unsaved models survive the last pane unmount, in window memory. Never persist draft content in localStorage.
- Document replacement revisions advance only after external content is accepted. Own saves must not rebuild the document or move its caret. The lazy editor must read the latest props when its chunk resolves.
- Edit with agent saves first, then calls the tab's own session `inputActions.insertQuote` and `insertText`. Never call `submit` or `setDraft`, and never infer a conversation from an artifact's source session. Surfaces without `inputActions`, such as the left full page, copy the same text instead.
- `src/client/review.ts` builds the quote and the artifact reference (title, id, workspace id for a workspace artifact, saved version). Only the selected text travels; never include the whole artifact or a stale copy of its content.
- Agent tools default to the session's workspace. An explicit `workspaceId` must resolve through the workspace registry before any path is built; never search workspaces by artifact id, and never combine it with the library scope.
- Preview frames get `SELECTION_BRIDGE` so a selection inside the page becomes a quote. The listener accepts only messages whose `event.source` is that frame; a page can at most fill a quote the user still reviews before sending.
- The chat card opens the artifact tab only when it watched the call run before the result arrived; a card that mounts already settled, as on transcript replay, never opens a tab.
- The right sidebar registers two types: `dsh-artifact-studio/artifact` for one artifact and `dsh-artifact-studio/artifacts` for the workspace page (guide entry, order 30). The page is session-bound through `useWorkspaceBinding`, reuses `GalleryBody` and `ArtifactPanelBody` in place, and lists only that workspace.
- Gallery covers are scriptless, opaque-origin iframes. Keep `sandbox=""` and strip scripts and inline handlers; a cover is decoration, not a second preview.
- Pins are local view preferences in `localStorage`. Never write them to a manifest, a version, or the host.
- Export and print accept an optional saved version. Never fall back to latest when a requested version is missing. Scope-root confinement must run before creating directories.

- Generation layers live in `src/host/lib/recipes.ts`, `guide.ts`, and `brief.ts`. Guide recipe IDs replace whole definitions by workspace, library, then built-in precedence. Invalid saved guides fail instead of being overwritten.
- `src/kit.ts` implements opt-in kit versions; `src/html-tags.ts` scans opening tags without repeated rescans on truncated HTML. A kit version does not pin current design tokens. Recipe metadata is artifact-level, not part of version snapshots.
- Covers strip scripts after composition because the kit injects a script. Preserve the doctype after serialization. Recomposition replaces host-marked styles and switch initialization is idempotent.
- Library artifacts and briefs resolve library context, never the calling workspace. The next named-system phase needs one snapshot resolver for preview, cover, print, export, and restore.
- Named design systems live in `<scope>/design-systems/index.json` with immutable `<ds_id>/<n>.json` revisions. Saves are compare-and-set on the index revision; artifact writes take an exclusive `<path>.write-lock` file. A stale lock after a crash is cleared by hand, never automatically.
- Every accepted Page or Document version stores `versions/<n>/generation.json` (tokens, system identity, recipe definition, kit, conventions digest) and a bounded summary in `meta.json`. Reads validate it and fail `artifact/corrupt` rather than falling back to live tokens. Ordinary edits reuse the current snapshot; only `artifact_rebase` adopts newer settings. A change to the token shape is a migration for every existing snapshot.
